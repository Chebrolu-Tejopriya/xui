# 0022 — Coin icons are a second family, kept faithful rather than tokenised

Status: accepted

## Context

The XUI Figma file carries a `Coin Type` component set (`2441:12895`): 48
transaction-type badges — External Deposit, Airdrop, Burn, Repay Loan — grouped
by Deposit / Withdrawal / Expense. They identify a row in a ledger.

They look like icons and are not. Reading the set's own properties:

| | Icons v2 | Coin Type |
|---|---|---|
| Size | 24px glyph | fixed 40x40 badge |
| Tones | four (outlined / solid / dualtone / dualtone-selected) | one |
| Colour | `currentColor` | its own palette |
| Bound to a variable | yes | **369 fills, none** |

The palette is `#4F677E` for the disc and `#26D0FF` / `#2AFF95` for the glyph.
None of those exist anywhere in the XUI ramp — the nearest greys, blues and
greens are all different colours. So there is no honest mapping to tokens, only
an invented one.

## Decision

**A second family, generated by its own pipeline, shipped exactly as Figma
paints it.**

`scripts/gen-coin-icons.mjs` reads `scripts/coin-icon-data/` — an `index.json`
of node ids, categories and names, plus one SVG per icon exported straight from
the file — and emits `src/icons/coin-icons.tsx`. Nothing retypes a path, so a
re-export is the only way this drifts.

The output is marked `xui-lint-ignore-file` as brand artwork, with the reason
written into the header: the set binds no variables and its palette has no XUI
equivalent, **so these do not follow the theme**. That is recorded as a fact
about the design, not a decision made in code — and as an open question on
Guides > Status.

`createCoinIcon` mirrors `createIcon`'s contract (a `size` prop, `aria-label`
promoting it from decorative to `img`, the shape hoisted to module scope per
ADR 0011) but takes one shape, defaults to 40, and ignores `color`.

## Alternatives rejected

**Map the palette onto XUI tokens.** The tidy answer, and it would make them
theme-reactive like the empty-state illustrations. Rejected because the
illustrations were already *on* the blue ramp — binding them to tokens was
reading a value, not choosing one. Here every colour is off-ramp, so any mapping
is a designer's decision being made by an implementer. ADR 0001 and ADR 0006
both point the other way.

**Fold them into Icons v2 and `gen-icons.mjs`.** They would need a fourth tone
that is not a tone, a second viewBox, and an escape hatch from `currentColor` —
three exceptions inside a generator whose value is that it has none.

**Ship them as static SVG files rather than components.** Simplest, and it
loses tree-shaking, the type union, and the `size`/`aria` contract every other
icon has. It also reintroduces the bug ADR 0011 exists to prevent.

**Wait for the designer to bind the variables first.** Correct in principle and
blocking in practice: the icons are needed now, and the extraction is
regenerable — when the file is fixed, one re-export and `npm run ds:build`
picks it up.

## Consequences

- 48 components, tree-shakeable, plus `coinIconCategories` and `coinIcons` for
  the gallery to iterate. `Foundations > Coin Icons` renders them grouped as the
  set groups them.
- **They do not respond to `data-theme`.** On a dark page they are the same
  slate disc as on a light one. That is faithful; whether it is right is the
  open question.
- The extraction found defects in the set, which are now recorded rather than
  silently normalised: `#2BFF95` on four fills where every other green is
  `#2AFF95`; strays `#1CD278` and `#D9D9D9` (Figma's default placeholder grey);
  two components both named **Dust**; and **Lost** beside **Lost1**.
- Figma renders a component inside its set, so every export arrives wrapped in
  the set's chrome — a `#AAAAAA` backing rect, a white board and the purple
  `#9747FF` dashed frame, all 1413x460 at negative offsets. The generator takes
  only the `<g id="Property 1=...">` group. **The first generated pass shipped
  the chrome**, and the palette line the generator prints is what caught it.
- Figma exports its layer names as ids, so all 48 carried `id="Vector"`. Those
  are dropped; ids that are actually referenced (clip paths) are kept and
  namespaced per component.
- Category is taken from the file, and the file disagrees with the reference
  implementation in several places — `Spend`, `Liquidity Out`, `Mint` and
  `UnStake` sit under different headings there. The file wins; the disagreement
  is worth a designer's eye.
